# CRM MA 活动草案创建设计

[English](2026-09-03-crm-ma-campaign-draft-design.md) | 中文

## 状态

已在对话中确认；编写实施计划前等待书面规格审阅。

## 目标

扩展 CRM 营销建议流程，使用户能够预览受治理的单链路活动画布，并在第二次明确确认后创建真实但未启动的 MA 人群和活动草案。创建草案不会启动触达。

## 与营销建议设计的关系

本设计扩展 [CRM 营销建议设计](2026-09-02-crm-marketing-recommendations-design.zh.md)。它只针对这里定义的显式 `crm_campaign_create_draft` 操作，替换原设计禁止写入营销平台的边界。建议评估与活动方案生成仍然只使用汇总数据并保持只读。

## 部署范围

部署使用 `tenantId=mkt`、`buCode=catering` 和 `collectionId=mkt_catering_loyalty`。首个执行链路由 MA 管理人群，因此 CDP 不创建该人群或生成快照。MA 创建人群和未启动的活动草案。LOYALTY 提供白名单卡券模板元数据和汇总履约结果；创建草案不会发券。

首期不包含提交审批、启动、暂停、恢复或停止活动、直接发送消息、直接发券、任意画布编辑、客户导出和自动清理。

## 架构

MA 与 LOYALTY 均使用完整的 Service Definition、Provider 和 Consumer 能力接口。Provider 负责 HTTP 协议、凭据、超时、响应限制、远端错误转换和部署配置。Consumer 向 CRM 插件暴露闭合业务操作，而不是原始 HTTP 请求。

MA Provider 读取受治理的目录、预估人群、校验和预执行画布、创建人群、创建未启动的活动草案，并读取活动与触达状态。LOYALTY Provider 读取白名单卡券模板和参与、领取及核销的汇总结果。两个 Provider 都不会向模型返回客户记录。

端点和凭据由部署管理。无认证部署必须设置 `allowUnauthenticated: true`；否则缺少凭据会导致 Provider 配置失败。

## 受治理的人群创建

每类营销机会引用一个已配置的人群策略。策略通过白名单定义 MA 标签或字段、运算符、证据到取值的映射、必须排除项、最大预估规模和允许动作。确定性代码从已持久化的建议证据解析策略。

模型不能提供 MA 表达式、任意字段、运算符、标签、客户 ID 或完整 `AudienceInfo` 请求体。Provider 代码把解析后的策略转换为 MA 协议。条件缺失或预估人群过大会使方案不可创建。

预览只包含汇总人数和有界分布。首个执行链路不会创建 CDP 快照、导出人群或读取 MA 人群成员。

## 受治理的单链路画布

画布包含一个 MA 人群入口、最多一个已配置条件、一个动作和一个结束节点。动作可以是一个已审批的 MA 触达模板，或者通过白名单 MA 权益能力引用的一个已审批 LOYALTY 卡券模板。

配置负责节点类型、连接、能力 ID、模板 ID、变量模式和允许的日期行为。模型只能选择白名单逻辑 ID 和有界的用户可见值。代码生成全部节点和连线；模型与用户不能提交画布 JSON。

规划器校验引用目录，调用 MA 画布校验，并在标记方案就绪前运行 MA 预执行。校验失败、模板不可用、日期无效、人群超限或预执行出错都会使方案保持不可创建，并说明具体原因。

## 明确创建活动草案

`crm_campaign_plan` 持久化预览和不透明方案 ID，不执行外部写入。本地化的“创建活动草案”按钮准备一条可见确认请求，但不会提交。用户必须提交该请求，Agent 才能调用 `crm_campaign_create_draft`。

`crm_campaign_create_draft` 只接受当前会话中的方案 ID 和明确确认值。它拒绝模型提供的证据、人群规则、字段、标签、模板、画布节点、端点和 Provider 请求体。外部写入受宿主审批机制保护。

操作重新校验方案、人群预估、目录、画布校验和预执行，然后创建或复用 MA 人群并创建未启动的 MA 活动草案。结果只包含外部人群 ID、活动 ID、未启动状态、安全查询元数据和有界警告。

## 幂等与部分失败

幂等键由租户、建议 ID、方案版本、人群策略摘要、所选动作模板和活动日期计算。会话事件保留幂等键、解析输入摘要、MA 人群 ID、MA 活动 ID、操作状态和有界错误详情。

存在已完成匹配时直接返回记录结果。人群创建成功而活动创建失败时，重试会复用已记录的人群。写入超时且结果不明确时，必须先通过外部业务键查询；Provider 无法解析该键时，操作报告需要人工核对，不会重复写入。

同一幂等键存在冲突记录时关闭失败。系统不会自动删除外部人群，因为删除属于独立的破坏性操作。

## 结果回收

只读工具解析已记录的活动 ID，并组合 MA 活动状态、流程状态和触达汇总，以及 LOYALTY 参与和卡券汇总结果。只有存在已配置的归因窗口和活动引用时，CRM 订单指标才提供转化结果。

报告保留周期、覆盖、归因规则和限制。只有存在有效对照组或比较设计时才说明增量效果。触达或核销数量本身不能证明增量销售。

## 安全与失败处理

配置错误在启动阶段失败。未知或跨会话 ID、任意人群字段、表达式、非白名单模板、错误日期、超大结果和包含客户数据的结果在发布前失败。远端错误只暴露安全的服务名、操作名、状态类别和关联 ID，不把响应体复制到模型可见输出。

凭据通过仓库凭据服务或具名环境变量提供，不能进入模型输入、会话事件、日志或客户端元数据。Provider 使用显式 HTTP 许可、有界读取、已配置超时，并在部署支持时分离读写凭据。

## 测试

Provider 测试使用本地 HTTP 夹具验证准确协议，不执行真实写入。配置测试拒绝任意字段、表达式、节点、模板、凭据和隐式无认证。单元测试覆盖人群策略、画布生成、幂等、写入结果不明确、部分失败和当前会话解析。

工具和客户端测试覆盖审批、结果限制、事件持久化、重放、本地化确认、回退呈现和无障碍。Web 组合和无密钥快照固定模型可见流程。真实环境验收只有在用户确认最终预览后才创建一个名称明确的未启动 MA 人群和活动草案，并记录人工清理所需 ID。

## 文档

CRM 指南将说明受治理的人群规则、画布预览、明确创建草案、未启动状态、恢复和结果解释。Provider 包 README 将说明配置、认证、协议责任、错误、幂等支持和外部系统限制。已实施 Agent Note 将记录证据、方案预览、明确外部写入与触达执行之间的分离。
