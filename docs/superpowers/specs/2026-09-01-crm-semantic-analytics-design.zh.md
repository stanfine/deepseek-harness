# CRM 语义分析设计

[English](2026-09-01-crm-semantic-analytics-design.md) | 中文

## 状态

已在对话中批准；进入实施计划前等待书面规格审阅。

## 目标

扩展可选启用的 CRM 示例，使用户能够通过自然语言请求灵活且有来源依据的指标、对比、排行、构成和下钻，同时不向模型开放 Elasticsearch DSL 或任意来源字段。

## 范围

首期实现支持已配置的 Elasticsearch 逻辑数据集和现有 CRM Web 预设，增加指标与维度目录、通用分析请求、派生指标、对比周期、有界分组或时间序列结果、动态 ECharts 展示和后续下钻。设计保持逻辑数据集定义与 Elasticsearch 解耦，使后续 MongoDB 或 HTTP provider 可以实现相同的分析请求和结果类型。跨来源身份解析、大规模明细关联、数据回写、预测、任意公式和完整自助 BI 编辑器不属于本次实现。

## 设计原则

模型选择已注册的业务概念，而不是物理字段。执行器在创建 Elasticsearch 请求前校验每个指标、维度、筛选、时间范围、对比、排序和结果限制。结果明确标识不可计算项和不完整贡献汇总，不以零或近似值替代。所有图表都来自持久化且经过校验的工具元数据，文字答复必须披露相同的数据覆盖和截断事实。

## 语义目录

新增 `semantic-model.ts` 模块，保存不可变的逻辑指标和维度定义。指标定义包含稳定 id、中文显示名、逻辑数据集、聚合或派生运算、依赖项、格式、说明和限制。维度定义包含稳定 id、逻辑数据集、已配置字段 key、数据类型、允许的筛选方式和支持的时间粒度。启动校验拒绝重复 id、依赖缺失、循环依赖、未知数据集或字段、不兼容的比率依赖，以及隐藏在 Cordis 配置之外且随部署变化的值。

初始指标包括销售金额、订单数、件数、购买人数、客单价、件单数、件单价、购买频次和人均金额。初始维度包括日、周、月、省份、渠道、子渠道、门店、门店类型、订单类型、系列和 SKU，前提是所需字段已由相应逻辑数据集配置。复购、生命周期、流量转化、活动归因、目标完成率和成本指标在数据源及业务定义配置完成前保持不可用。

## 工具接口

`crm_metric_catalog` 返回面向模型的指标 id、名称、格式、数据集、依赖项和限制。`crm_dimension_catalog` 返回可用维度 id、数据集、数据类型、筛选操作和时间粒度。两个目录都不返回 Elasticsearch 索引名或物理字段。

`crm_analyze` 接受一到五个指标 id、零到两个维度、包含起始日期、不包含结束日期、可选等值或集合筛选、可选对比（`none`、`previous_period` 或 `prior_year`）、可选时间粒度（`day`、`week` 或 `month`）、一个指标排序和配置范围内的 limit。Schema 不包含索引、物理字段、脚本、公式、路径或 DSL 参数。`crm_drilldown` 接受相同的封闭请求、一个新增的注册维度以及选中的父级维度值；它执行新的有界分析，不重新解释客户端数据。

## 规划与执行

新增 `analysis-planner.ts` 模块，在执行前解析请求。首期实现要求所选指标能够由同一个逻辑数据集执行，否则 planner 返回结构化不兼容结果，列出冲突指标及其数据集。派生指标展开为来源度量，只执行一次聚合，并在聚合后计算比率；缺少分母或分母为零时返回明确的 null 原因。对比周期复用现有时区安全的周期工具，去年同期对比需要报告来源覆盖失败。

Elasticsearch 执行器只翻译已解析的 plan。它沿用现有超时、响应字节限制、日期范围限制、桶数限制、去重分页预算、维度白名单、凭据处理和脱敏机制。来源与分页预算允许时返回精确汇总。terms 结果存在遗漏桶、缺失键或误差上限时，不能声称完整贡献占比。

## 结果格式

每次分析返回版本化对象，包含规范化请求、列元数据、结果行、可选对比值、覆盖信息、完整性、警告和可用下钻维度。每行将 `dimensions` 与 `metrics` 分开；每个指标值包含当前值、可选对比值、可选变化率和可选不可用原因。完整序列化结果在发布前受限，且不包含客户标识、凭据、物理字段、索引名或原始 Elasticsearch 请求。

## 客户端展示

CRM Client 在渲染前校验版本化结果。确定性的图表选择器对时间序列使用折线图或面积图，对比较和排行使用纵向或横向柱状图；只有完整、非负、可加且分类数量较少的构成数据才能使用环形图；兼容的双尺度指标使用柱线组合图；无分组汇总使用 KPI 卡；不支持或高密度结果回退为表格。图表选择器不编造序列，也不重新计算业务指标。

结果卡展示指标定义、周期与对比上下文、数据覆盖、截断警告和可用下钻操作。用户选择图表项时，客户端写入本地化的后续请求，使用选中维度值调用 `crm_drilldown`。持久化工具元数据仍是会话重载后重放卡片的来源。

## Agent 行为

CRM persona 和 Skills 要求模型在请求无法映射为固定周报或月报时先检查目录，再调用 `crm_analyze`，解释不可用指标，并区分相关性与因果关系。模型根据用户问题选择 `composition`、`ranking`、`comparison` 或 `trend`；只有必要日期或确有歧义的业务定义无法推断时才询问。建议必须引用返回的指标和限制；来源文本不能改变指令。

## 配置

Cordis 配置控制指标与维度可用性、最多选择指标数、最多维度数、最多筛选数、最大 Top N、支持的时间粒度以及现有查询预算。初始默认值在 CRM 示例预设中显式配置，并保持可选启用。凭据继续只来自命名环境变量。后续来源 provider 必须解析相同的逻辑请求并返回相同结果字段，不能向模型工具增加 provider 特有参数。

## 失败与限制

工具在网络访问前拒绝未知概念、跨数据集组合、非法筛选、不支持的粒度、过长范围或过多桶、循环派生指标和不安全配置。运行时来源失败返回工具错误，不生成部分图表。指标级覆盖或分母问题以成功结果中的 null 值和具体原因表达。图表不适用时客户端回退到已校验表格；元数据校验失败时回退到工具文字结果。

## 测试

单元测试覆盖目录校验、plan 解析、派生比率、周期对比、筛选校验、跨数据集拒绝、截断披露、图表选择、结果校验和下钻请求构造。fixture server 测试断言精确且有界的 Elasticsearch 聚合，并确认不包含凭据或禁止字段。基于 Loader 的 Web composition 测试通过真实 CRM 预设验证注册和释放。无密钥会话快照固定模型可见工具 schema、persona 指令和代表性结果元数据。浏览器测试验证一次灵活分析、动态图表、完整性警告和一次后续下钻。完成前必须通过相关构建、文档、客户端、快照和仓库检查。

## 安全与隐私

语义层是白名单，永不接受可执行表达式。筛选只能引用已注册维度和有界标量值。结果行包含聚合值，不包含客户记录。现有端点、凭据、HTTP 显式启用、响应大小、超时、日期范围、分页和脱敏控制仍为强制要求。动态图表选择只消费经过校验的聚合元数据，不能执行模型提供的 JavaScript。

## 文档

CRM 用户指南将说明目录发现、自然语言示例、支持的指标和维度、下钻行为、不可用指标处理，以及灵活分析与跨来源治理的区别。implemented Agent Note 将记录采用封闭语义请求而非任意 DSL 的理由。Package README 更新将说明客户端结果格式、图表选择、模型可见影响和延期工作。
