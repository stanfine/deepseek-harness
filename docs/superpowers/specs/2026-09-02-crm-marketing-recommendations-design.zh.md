# CRM 营销建议设计

[English](2026-09-02-crm-marketing-recommendations-design.md) | 中文

## 状态

已在对话中批准；实施规划前等待书面规格审阅。

## 目标

扩展可选 CRM 示例，使用户能够分析聚合数据、获得最多三条有来源证据的营销机会、从卡片选择一条机会，并生成带聚合人群预览的活动方案草稿。第一期实现不导出客户记录、不发布活动，也不写入营销平台。

## 范围

第一期实现使用现有 CRM 语义目录、分析执行器、Web 预设和持久化 CRM 卡片。它增加已配置的机会类型、确定性候选规则、模型辅助解释、建议卡片、活动方案草稿和聚合人群预览。客户身份导出、消息内容生成、审批工作流、预算、投放连接器、人群物化、写回、定时、归因和自动执行不在本期范围内。

## 用户流程

用户先通过现有 CRM 工具请求分析，然后为指定周期和对比方式请求营销建议。系统使用新的语义查询评估已配置的机会类型，返回不超过三条有证据的建议，并解释不可用类型。建议卡片按钮将本地化的活动方案请求写入输入框草稿。用户提交请求后，系统才创建方案草稿。

## 设计原则

建议引擎把分析作为证据，不把分析视为执行授权。部署配置拥有每种机会类型、必需指标、维度、阈值、活动机制、核心指标、护栏指标和允许的人群条件。确定性代码判断候选是否成立并分配证据分数。模型可以解释和排序有效候选，但不能创建新的活动类型、修改阈值、提交来源字段或把草稿变成可执行活动。

## 机会目录

配置定义 `reactivation`、`repurchase_growth`、`channel_optimization`、`store_improvement`、`atv_growth` 和 `items_per_order_growth` 的封闭目录。每项定义包含稳定 id、本地化名称和描述、必需语义指标和维度、对比类型、最低覆盖、受限规则、支持的渠道或机制、人群条件 id、核心指标、护栏指标和限制。启动校验拒绝重复 id、不可用语义依赖、跨数据集需求、不支持的对比、无效阈值、未知人群条件及无法产生证据的规则。

只有必需语义概念能从一个逻辑数据集获得，且来源覆盖达到配置最低要求时，机会才可用。部署无法证明最近购买、历史消费、同意状态或客户身份要求时，会员召回和高价值复购保持不可用。目录将这种情况报告为受治理的拒绝，不报告为零机会。

## 建议评估

`crm_recommend_opportunities` 接受包含首日、不包含末日的日期范围、对比类型和可选的受限机会 id 列表。schema 不接受索引、物理字段、公式、脚本、DSL、任意规则或任意活动类型。评估器把每个选中机会展开为固定语义分析请求，通过现有规划器和提供方执行，校验覆盖与完整性，应用配置规则，并保留规范化请求作为证据引用。

每个候选根据证据强度、预计影响、完整性和配置风险获得确定性分数。评估器按分数返回不超过三条候选，并附带已配置的标题和行动模板及计算所得证据字段。模型可以在助手回复中概述这些持久化字段，但不能向建议对象写入自由文本，也不能引入不支持的指标、人群条件、渠道或机制。

## 工具接口

`crm_opportunity_catalog` 返回机会 id、业务描述、必需概念、可用状态、不可用原因、核心指标、护栏和限制。`crm_recommend_opportunities` 返回版本化建议并持久化 `{ crmRecommendations: { version: 1, request, data } }`。`crm_campaign_plan` 只接受能解析到当前会话有效持久化建议的建议 id，并持久化 `{ crmCampaignPlan: { version: 1, recommendationId, data } }`。

工具所有者从会话日志解析不透明建议 id。调用方不能提交建议证据、分数、人群数量、活动机制、来源请求或方案状态。这样可以保持模型可见输入精简，并确保每项模型可见建议和方案都能从记录事件重建。

## 建议结果

每条建议包含稳定建议 id、配置类型、确定性优先级和分数、证据记录、聚合人群条件、预计人群预览、建议渠道和机制、核心及护栏指标、限制和规范化来源请求。证据记录包含逻辑指标和维度 id、当前值和对比值、覆盖、完整性及不可用原因。结果不包含物理字段、提供方请求、凭据、客户 id 或客户记录。

## 活动方案

活动规划器把一条持久化建议转换为 `draft` 方案。方案包含目标、证据假设、已配置人群条件、聚合人群规模和分布预览、排除检查清单、建议渠道和机制、建议周期、实验组和留出组指导、核心指标、护栏指标、限制、风险及执行就绪检查清单。第一期实现不公开 `draft` 以外的状态，也不提供发布、审批、导出、定时、发送或变更方案的操作。

人群预览使用已配置的聚合语义查询。它返回计数、受限分布、覆盖和不可用原因，不返回姓名、手机号、邮箱、客户 id、文档预览或叶级记录。无法评估的条件返回不可用原因，并阻止方案声称存在可执行人群。

## 客户端展示

CRM 客户端把建议和活动方案元数据作为不可信的持久化 JSON 进行验证。它校验版本、字节和条目限制、id 格式、已知机会类型、逻辑指标和维度 id、证据一致性、人群条件允许列表、仅草稿方案状态，以及不存在客户记录或执行字段。无效元数据回退到文本工具输出。

建议展示转换器最多渲染三张可访问的机会卡片，显示优先级、证据、覆盖、人群条件、预计规模、建议机制、指标、风险和限制。“生成活动方案”按钮使用建议 id 和可见业务上下文调用 `inputActions.setDraft()`，不提交草稿也不调用工具。方案展示转换器渲染聚合预览、实验指导、指标定义、风险和就绪检查清单。刷新或重启后，持久化元数据仍是回放来源。

## Agent 行为

CRM persona 先使用现有分析工具回答用户的数据问题。只有用户请求营销建议后，它才调用机会目录和建议评估器。它区分观测证据与建议干预，解释不可用机会类型，并且没有实验时不声称预期提升。用户选择建议后，它只根据已提交草稿调用 `crm_campaign_plan`，并把结果描述为供人工执行的准备材料。

## 失败处理

配置错误在启动时失败。不支持的机会类型、无效周期、不可用概念、跨数据集需求、超限请求、缺失的持久化建议 id 和过大结果在发布前失败。仅当配置规则允许部分覆盖且结果保留警告时，不完整但可用的证据才产生建议。必需条件或聚合人群估算不可用时，活动方案不能声称已准备执行。

## 安全与隐私

所有数据访问复用语义允许列表、提供方超时、响应限制、日期限制、凭据隔离和仅聚合结果规则。模型不能引入查询表达式、客户标识、投放目标、内容载荷、预算、可执行操作或外部端点。第一期实现不增加写入凭据，也不增加具有变更权限的连接器。建议和方案按钮只准备用户可编辑草稿，不执行网络操作。

## 测试

单元测试覆盖配置校验、不可用类型、确定性规则评估、分数排序、三条结果限制、证据一致性、会话范围建议解析、聚合人群预览和仅草稿方案。运行时测试证明封闭工具 schema、访问来源前拒绝、结果大小限制、销毁，以及不存在物理字段或客户字段。客户端测试覆盖持久化校验、卡片、本地化草稿构造、回放、无效元数据回退和可访问性。基于 Loader 的 Web 组合测试和无密钥快照固定工具、persona、代表性建议、方案及持久化元数据。浏览器测试验证从分析到建议、卡片选择、草稿确认、方案渲染和重启回放，并且不发布活动。

## 文档

CRM 指南将说明建议优先流程、已配置机会类型、数据不可用行为、聚合人群预览，以及方案草稿与活动执行之间的区别。客户端包 README 将说明元数据校验和卡片行为。implemented Agent Note 将记录分离证据、确定性候选选择、模型解释、人工选择和执行的决定。
