# Agent Note: 基于数据源的 CRM 周报

Status: proposed

[English](2026-09-01-crm-weekly-report.md) | 中文

## 问题

CRM 示例能够查询受限的订单和会员聚合，并为每次工具调用绘制一个结果，但无法生成 REMY 报表模板包含的业务章节。周报需要可比周期、可加销售指标、客户生命周期分群、产品贡献、数据源可用性，以及绑定查询证据的建议。当前数据源还包含未来日期记录和不完整的衍生索引，因此 Agent 不能将最新日期或空指标视为可信结果。

## 提案

CRM 预设增加基于固定 Elasticsearch 索引和允许字段的周报能力。数据保留在各源索引中。模型选择报告周并调用领域工具；模型不能提供索引名、字段名、查询 DSL、脚本、客户标识或算术表达式。

报告周采用配置 UTC 偏移下的周一 00:00 至下周一 00:00。环比周期是此前七天。去年同期将两个端点向前移动 364 天，从而保持星期对齐。财年累计从部署配置的财年起始月开始，截止报告周的开区间结束日期。范围结束时间晚于当前日期时标记为未完成周期，不能作为完整周展示。

### 数据角色

配置将逻辑角色映射到精确索引和字段。`orders` 负责文档级探索查询。`orderFacts` 负责可加的订单金额、订单数、商品数量和客户日事实。`orderItems` 负责商品行金额、数量、系列和 SKU。`members` 负责注册。`repurchases` 负责已观察的复购事件。每个角色声明金额含义、时间字段、身份字段、维度、源过滤条件和公开覆盖要求。缺失角色在报表中显示为不可用章节。

读取器在加载时验证所有角色、字段路径、日期范围、分桶预算、响应预算和凭据引用。读取器在聚合前应用部署拥有的过滤条件，例如最低订单金额。读取器拒绝部分分片、超时、重定向、不精确总数和耗尽的精确计数分页。结果披露缺失值、省略分组、数据覆盖，以及指标是否精确。

### 周报工具

`crm_report_periods` 接收请求周内的一个日期，返回标准的本周、上周、去年同期和财年累计窗口。该工具集中处理周期计算，防止模型选择星期不一致的范围。

`crm_sales_report` 为每个可用比较窗口返回一行源金额、订单数、购买客户、复购客户、商品数量、订单均价、件单量、件单价、购买频次和客均金额。当分母为零或输入不可用时，比率返回 null 和原因。客户数使用有预算的 composite 分页，且从不返回标识。

`crm_lifecycle_report` 仅在数据覆盖包含全部所需历史窗口时，返回新客、存量新客基数和活跃数、留存基数和活跃数、召回基数和活跃数及相应比率。实现在有预算的 Elasticsearch composite 分页中分类客户，只输出计数。分页或时间预算耗尽时，整个指标失败，不能返回部分计数。注册数与首购分群保持分离。

`crm_product_report` 按系列或 SKU 对配置的商品行数据源分组，返回有限的金额、数量和商品行文档贡献。结果披露省略分组和缺失商品键。工具不会将商品行文档数称为订单数，不推断 UV，也不使用文档级订单索引中为空的 nested `items` 字段。

只有配置的数据源提供访问量和稳定渠道键后，才注册 `crm_traffic_report`。缺少该角色时，周报声明 UV、注册转化、购买转化和广告归因为不可用。工具不能从订单或注册数推导访问量。

### 展示和建议

客户端将对比结果绘制为基于数据源的 KPI 表，包含本期、上期、去年同期和财年累计列。客户端将周趋势绘制为折线图，将完整结构绘制为环图，将排行绘制为横向条形图。客户端保留源数据表、覆盖警告和 null 原因。客户端验证持久化元数据，且不接受模型编写的 ECharts 选项或数值。

业务 Skill 生成数据覆盖、管理摘要、销售、生命周期、渠道、产品、模板不可用指标、建议和指标定义章节。每条建议包含观察、证据引用、标记为假设的原因、行动、验证指标和限制。缺少流量或分群证据时，不能提出预算、归因或客户定向建议。Agent 不输出客户级名单，也不触发营销动作。

### 限制示例的数据源发现

配置的集群提供专用订单事实、订单商品宽表、复购和客户订单日索引。订单商品宽表映射提供商品行级系列、SKU、金额和数量。观察到的数据覆盖截止 2025 年 5 月，并且会员 `firstBuyDate` 字段没有值。文档级订单数据源包含直到 2029 年的未来日期。因此报表在选择周期前检查覆盖，并说明示例数据可能是历史或模拟数据。这些观察只配置示例，不成为可复用读取器的内置假设。

## 已考虑的替代方案

**通用 Elasticsearch 或联邦查询工具。** 通用工具可以减少每个指标的实现，但会允许模型参数选择字段、连接或 DSL，从而绕过报表语义和隐私审查。提案中的工具保持取数和算术封闭。

**先建设统一数仓。** 治理后的数仓可以简化客户身份、归因和历史快照，但会延迟可用的源数据报表，并超出第一阶段要求。配置的数据角色允许未来提供方使用治理表，而不改变模型可见的报表概念。

**仅用提示词生成报表。** 提示词不能让缺失的流量、历史覆盖或商品数据变得有效，也不能保证周期对齐或客户精确计数。提案将这些要求编码在工具行为中，并向 Skill 返回不可用原因。

## 验收标准

- 用户可以请求周一至周日的 CRM 周报而不需要指定查询模式，Agent 使用标准的本周、上周、去年同期和财年累计窗口。
- 销售输出只使用配置的可加字段进行计算，分母为零或缺失时返回 null，并区分文档、订单、商品行文档和客户。
- 生命周期输出返回不含标识的精确有限计数，或明确拒绝历史或分页不完整的指标。
- 产品输出使用商品行宽表角色并披露省略或缺失分组；缺失的流量保持不可用。
- 会话包含基于数据源的表格、适当图表，以及可以检查证据和限制的建议。
- 单元测试覆盖周期边界、聚合请求编译、比率失败、分页耗尽、覆盖拒绝、产品截断、元数据验证和建议指令。真实 API 测试只检查聚合，无密钥会话快照记录模型可见工作流。

## 风险

不同数据角色中的客户标识可能不一致，查询成功不能证明跨索引身份一致。实时 composite 分页不提供时间点快照。在部署所有者验证之前，源金额和订单字段可能不符合模板的 GMV 和交易定义。Top 产品分组可能遗漏长尾。未来日期或不完整的数据覆盖可能使请求周不可用。报表披露这些条件，不用零替代、不外推，也不编造建议。
