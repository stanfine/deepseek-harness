# Agent Note: 闭合的 CRM 语义分析与下钻

Status: implemented

[English](2026-09-01-crm-semantic-analytics.md) | 中文

## Problem

固定 CRM 报表可以回答已知的周报和月报问题，但用户还需要指标、对比、排行、构成和后续下钻，无法为每个问题逐一注册工具。开放 Elasticsearch 字段、查询 DSL、公式或图表选项会让模型参数绕过业务定义、隐私审查和取数限额。配置数据还分布在不同逻辑数据集中，相同名称不能证明可以安全关联或拥有一致的客户身份。

## Decision

来源求和同时发布 `missing`；匹配文档缺失配置字段时，该指标不可用，比率会传播此状态。两种对比方式都要求配置时区下的观测历史覆盖对比起点。日期过滤编译为本地日的半开区间，所有日期分组在访问数据前检查桶预算，趋势按时间顺序保留全部预算内桶且不应用 Top N 截断。持久化列携带闭合的指标可加性与维度构成语义，因此环图只接受可加指标和互斥类别。最终保留的 `{ content, meta }` 投影将转义后的工具文本、元数据和外层字段名一起计入 1 MiB UTF-8 发布预算。求和指标缺少配套的 missing 聚合时拒绝响应。缺失指标覆盖以 `missingMetricValues` 表示，这是可累加的指标值计数，可能超过来源文档数。未声明的维度构成记为 `unknown`；只有显式 `mutually_exclusive` 才允许环图。日期下钻父值保留其直方图粒度，并按相对桶位置映射到对比窗口。

CRM 预设提供不可变的指标和维度目录，以及 `crm_analyze` 和 `crm_drilldown`。部署配置将稳定的业务标识映射到一个逻辑数据集及其允许的源字段。规划器只接受目录标识、闭合的等值筛选、有限日期、支持的时间粒度、对比类型、排序指标和 Top N。它展开已配置比率的依赖关系，并在网络请求前拒绝跨数据集分析。Elasticsearch 执行器负责聚合 JSON、有限的精确去重分页、响应验证、对比对齐和完整性警告。

初始灵活订单指标使用有限的订单文档数据集，因为该数据集拥有交互下钻所需的渠道、子渠道、门店、门店类型和订单类型维度。描述保留源文档语义：部署所有者确认唯一性前，订单数是匹配文档数；销售额不代表净销售额或特定币种。固定周报继续使用专用的可加事实和商品行来源。一次请求不会把这些数据集的值当作来自一张受治理的表进行合并。

成功的工具把带版本的语义请求和结果持久化到会话元数据。客户端验证完整封装，包括列、行、对比值、覆盖范围、完整性、警告和允许下钻维度。客户端确定性生成指标、趋势、排行、对比、构成或表格展示。占比视图要求数据完整、非负且可加。模型和持久化数据都不能提供可执行 ECharts 选项。选择一行会生成保留已验证分析上下文的本地化草稿；用户提交草稿后，Agent 才能调用 `crm_drilldown`。

本记录负责灵活语义分析。[有限读取决策](../architecture/2026-08-31-crm-read-only-agent.zh.md)继续负责可选预设、凭据和旧固定查询能力。[周报决策](2026-09-01-crm-weekly-report.zh.md)继续负责专用周报事实、来源覆盖和证据约束建议。

## Alternatives considered

**让模型编写 Elasticsearch DSL 或 ECharts 选项。** 这种方式便于快速尝试陌生问题，但源字段、脚本、结果规模和可执行展示会脱离审查后的业务能力。

**查询时连接所有配置来源。** 字段名称相同不能证明客户身份、指标、归因或时间对齐一致。未来的数据提供方可以在同一语义请求之后实现受治理的联合数据集，但首个实现明确拒绝跨数据集选择。

**增加更多固定报表工具。** 固定工具仍适合受控模板和稳定报表定义。为每个临时排行或下钻继续采用该方式会重复模式和界面处理，无法形成可复用的业务词汇。

**由模型计算比率和对比。** 提示词中的算术不能可靠保留分母为零、分桶缺失和对比不可用的原因。执行器计算配置比率与变化值，并在每个值旁持久化空值原因。

## Consequences

用户无需了解源字段即可查询受支持的业务概念，并可从图表选择继续进入一个有限的后续维度。持久化元数据在历史重新加载后恢复相同图表和警告状态。目录将不支持的复购、生命周期、流量、归因、目标和成本指标连同具体限制保持可见，不会返回零。

目录属于部署工作：数据所有者必须确认文档唯一性、金额含义、身份、历史和筛选规则。配置会拒绝逻辑数据集没有可用指标的维度，使每个已公开维度都能参与至少一种有效请求。派生指标列重复其依赖项的重要限制，因为消费者可能在不保留源指标的情况下单独持久化或呈现所选列。一次请求不能核对 CRM、交易、活动、流量和成本系统之间的值。terms 聚合截断、维度缺失、实时索引读取和对比历史不可用保持可见。单元测试负责验证、规划、编译和客户端渲染；Web 组合测试负责实际预设注册及下钻元数据；`crm-catalog` 无密钥快照负责模型可见指令、模式、语义对比结果和持久化下钻元数据。Browser 运行时可用时，真实浏览器检查负责渲染交互。
