# Agent Note：CRM 周报 Excel 导出

Status: implemented

[English](2026-09-01-crm-weekly-excel-export.md) | 中文

## 问题

CRM 周报可在会话中检查，但无法交付为可复用工作簿。安全导出必须保留固定报表定义、不包含客户标识、披露不可用章节，并提供经过认证的浏览器下载，同时不能开放任意文件系统或查询接口。

## 决策

CRM 示例增加 `crm_export_weekly_excel`。它只接收日期，使用与会话工具相同的固定销售、生命周期、产品系列和产品 SKU 报告，并把结构化结果交给工作簿渲染器。模型不能提供单元格、公式、路径、索引、字段、ECharts 选项或 Elasticsearch DSL。

渲染器使用部署配置的 `@oai/artifact-tool` 模块。工作簿包含 Definition、Sales Overview、Lifecycle、Traffic、Product Series、Product SKU 和 Recommendations 工作表。源指标写为数值类型；比较率使用带保护的公式，基期为零或不可用时不会产生公式错误。工作簿展示数据源覆盖、未完结周期、不可用原因、截断警告，以及待确认的退款、取消、币种、最低订单金额、复购客户和身份口径。工作簿不包含客户标识或原始数据记录。

Host 拥有的导出注册表将文件写入部署配置的导出根目录，使用随机不透明 id 和固定 `.xlsx` 文件名。插件通过现有 connection 服务注册一个经过认证的 `/api/crm.export` fetch 路由。路由只接收不透明 id，拒绝路径穿越、未知或过期条目，并使用附件内容类型和 disposition 返回工作簿。条目在配置时间后过期，插件卸载时删除已注册文件。工具结果只持久化不透明 id、文件名、字节数、过期时间和工作簿摘要。客户端校验这些元数据后绘制指向认证路由的下载按钮。

建议保持证据约束。导出工具可接收有限数量的已生成建议，每条包含观察、证据、标记为假设的原因、行动、验证指标和限制。这些字符串只作为工作簿数据，不能影响查询、路径、公式或布局。未提供建议时，该工作表说明应先在会话中生成建议再重新导出。

## 结果

CRM 周报工作流现在可以把同一份固定、基于来源的报告交付为可复用工作簿，同时不开放通用表格或文件系统工具。Web 部署提供经过认证且有时效的下载；headless 部署保留分析工具，但由于没有下载路由而拒绝导出。部署所有者必须提供私有 artifact-tool 模块和可写导出目录。

## 测试

- 导出工具复用固定周报取数，不能接收查询或工作簿代码。
- 工作簿包含可审计数值输入、受保护公式、可见的数据源限制，且没有客户级数据。
- 浏览器只能通过认证 CRM 路由下载已注册且未过期的文件。
- 客户端元数据校验拒绝非法 id、文件名、大小和过期时间。
- 测试覆盖工作表、公式保护、隐私、路径限制、过期、路由清理、界面下载行为和 Web Loader 路径。

## 已考虑的替代方案

**由模型编写工作簿 JSON 或公式。** 这种方式可以支持任意布局，但不可信的模型输出将能够控制可执行表格内容、路径，并可能写入客户级数据。固定渲染器把布局和公式保留在经过评审的代码中。

**公开静态文件。** 直接提供导出目录会绕过经过认证的 connection 路由，也难以强制执行过期策略。不透明注册表不公开本地路径，只解析有效 id。

**在浏览器中生成工作簿。** 客户端生成会重复报表校验，并把部署专用表格基础设施移入 Web 包。Host 生成保留单一、可审计的实现，并返回普通附件。

## 风险

`@oai/artifact-tool` 是私有部署基础设施，因此必须显式配置；运行时缺失或不兼容时，导出明确失败，但不影响 CRM 分析。生成的工作簿捕获实时分页读取，而非时间点快照。文件在过期或应用关闭前占用本地磁盘。不同表格软件的图表渲染可能不同，因此源数据表始终是权威依据。
